# 기업별 제안 준비

기업 상세의 **제안 준비하기**에서 시작한다. 기본은 벤더 중립이다. **제안할 벤더**를 선택하거나 솔루션 이름을 직접 입력하면 해당 솔루션을 제안하는 세일즈 관점으로 추천·제안서·메일을 작성한다. 선택과 소개 내용은 기업별로 저장한다.

선택한 벤더의 **솔루션 소개·제안 조건 추가**에서 소개 문구, 제안 가능한 기능, 제외할 채널 등을 입력할 수 있다. 제품 상세 정보가 없으면 지원 여부를 단정하지 않고 적용 가능성을 확인할 제안으로 작성한다. 벤더·소개를 바꾼 뒤에는 다시 조사·추천을 거쳐야 한다. 새 추천이 실패해도 이전 기준의 문서를 최신 결과로 내보내지 않으며 원본은 이력에 보존한다.

상단 **종 아이콘**에서 회사 조사·추천과 제안서·메일 생성의 진행·완료·실패를 확인한다. 다른 대시보드 화면에서도 약 15초마다 갱신하며, 완료·실패한 작업은 새 알림 수에 포함된다. 알림을 누르면 해당 기업의 결과로 이동한다. 읽음 상태는 브라우저별로 저장하며, 브라우저를 닫았을 때 운영체제 알림을 보내는 기능은 아니다. 공용 대시보드이므로 최근 작업 알림도 함께 표시된다.

1. **회사 조사·추천받기**: 공식 홈페이지와 공개 마케팅 자료를 웹 검색하고 읽는다. 조사 결과·사업 특성과 Marketing Use Case KB를 종합해 3~5개 유즈케이스를 추천한다. 목표·채널·기능을 사전에 입력할 필요가 없다.
2. 추천 이유를 보고 **1~3개 선택**한다. 각 카드에서 실행 흐름, 필요한 데이터·동의·연동, KPI, 확인 질문과 근거를 펼쳐 볼 수 있다.
3. **선택 완료 · 제안서와 메일 만들기**: 선택한 시나리오로 제안서와 첫 연락 메일을 한 번에 생성한다. 두 결과 모두 검증된 경우에만 함께 저장한다. 제안서는 인쇄/PDF·텍스트, 메일은 복사·텍스트로 이용한다.

본문 편집·수정 저장은 제공하지 않는다. 시나리오를 다시 선택해 생성할 수 있고 이전 결과는 저장 이력에 남는다. 메일 발송·서비스 연동은 없다. 복사 후 메일 서비스에서 수신자와 발신자 서명을 확인한다.

## 조사와 추천 근거

- `web/preparation_research.py`는 선택한 백엔드의 공개 웹 검색·열람을 사용한다. Codex CLI 연동은 [설정 안내](CODEX.md)를 따른다. 기업명·업종·공개 URL·조사 날짜만 입력한다. 개인 문맥, 훅, 스킬, MCP, 파일·셸 도구와 세션 저장은 비활성화한다.
- 검색 후 실제 열람에 성공한 출처만 인정한다. URL은 검색 도구가 반환한 링크 또는 등록된 공개 대상 URL이어야 한다. Claude 경로는 실제 WebFetch 반환 텍스트, Codex 경로는 robots를 존중하는 별도 HTTP 본문 조회로 근거 발췌를 확인한다. 이 검사는 출처 이력을 확인하며, 모델의 요약 전체를 의미적으로 증명하는 것은 아니다.
- 회사 공개 자료는 `[W1]`, Marketing KB 패턴은 `[M1]`로 분리한다. 발행일을 모르면 미상으로 표시한다. 회사의 과거 활동이나 홈페이지 노출을 현재 전략 전체로 확대하지 않는다.
- 회사 자료를 충분히 확인하면 **회사 공개 자료 참고**, 자료가 부족하면 **유사 업종 기반 제안**으로 표시한다. 검색 장애와 근거 부족도 구분해서 알린다. 웹 조사 실패 시 업종별 KB 가설로 진행할 수 있지만, KB 검색 자체가 실패하면 근거 없는 추천을 생성하지 않는다.
- 추천은 사업 적합성과 근거를 고려한 검토 순서다. 구매 가능성·연락 가능성 순위가 아니다. 관측상 미검출을 사용 중단, 최초 검출을 신규 도입으로 해석하지 않는다.
- KB는 `market=kr`, `translate=false`로 조회하고 유사도 0.70 미만·제외 판정 결과를 거른다. 자동 추천은 조사에서 도출한 최대 3개의 질의 또는 업종별 고객 여정 질의를 사용한다. 각 질의의 결과를 번갈아 모아 최대 10개 패턴을 제공해 첫 질의의 편향을 줄인다.
- 여정 자동화, 상품·콘텐츠 추천, 고객 데이터, 개인화, 메시징, 실험 등 일반 기능을 폭넓게 검토한다. 명시적으로 선택한 경우에만 해당 벤더를 판매자로 삼는다. 선택한 벤더의 KB 사례가 검색 결과에 있으면 우선 검토하되 다른 벤더의 공통 패턴도 참고한다. 제품별 지원·동의·데이터 준비 조건은 확인할 사항으로 남긴다. 사용자 소개는 생성 모델에만 전달하며 회사 웹 조사 입력에는 포함하지 않는다.
- 모델에는 KB 패턴의 설명·기능·채널을 제공한다. 출처별 고객 성과 숫자는 전달하지 않으며 타사 성과를 예상 성과로 약속하지 않는다. 원문 제목·URL·벤더 귀속은 참고 자료에 보존한다.

## 생성·저장·운영

- 추천과 제안서·메일 생성은 사용자가 버튼을 눌렀을 때만 실행한다. 페이지 조회로 외부 모델을 자동 호출하지 않는다.
- 텍스트 생성은 도구가 차단된 별도 모델 호출이다. 회사별 저장, 리비전 확인, DB별 OS 잠금으로 중복·동시 생성을 제한한다. 검색·생성은 백그라운드 작업이며 수집 워커·예약 일정과 분리된다.
- 추천 재생성 시 이전 제안서·메일은 보관하되 최신 결과로 내보내지 않는다. 선택 변경과 두 문서 생성은 하나의 저장 단위다. 어느 한 문서라도 형식·출처 검증에 실패하면 기존 선택과 두 문서를 모두 유지한다.
- 과거 직접 편집 초안은 삭제하지 않는다. `generation_policy=research_led_v3` 이전 결과는 새 조사·추천을 거친 뒤 사용하며 이전 원본은 이력으로 내려받을 수 있다. 과거 편집 API와 단독 제안서·메일 생성 요청은 거절한다.
- 작업 중 해당 기업의 내보내기를 막는다. 서비스가 중단되면 작업을 실패로 표시하고 유료 호출을 자동 재실행하지 않는다. 출력 본문·개인 자료는 오류 로그에 남기지 않는다.
- 대시보드 전용 `RADAR_PREPARATION_ENABLED=1` 또는 `[preparation].enabled=true`로 활성화한다. `mkb_url` 기본값은 `http://127.0.0.1:8611`, 기본 경로는 기존 인증된 Claude CLI이며 `backend="codex"`로 Codex를 선택할 수 있다. 호출별 제한은 240초다. 조사·KB 검색·본문 생성이 이어지므로 전체 작업에는 수 분이 걸릴 수 있다.
