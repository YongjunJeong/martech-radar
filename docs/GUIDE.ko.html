MarTech Radar · 사용 설명서

설치부터 첫 신호까지

관심 있는 회사들의 공개 웹사이트를 매주 실제 브라우저로 방문해, 어떤 마케팅 솔루션이 실제로 돌고 있는지 기록하고, 무엇이 바뀌었는지를 영업 신호로 알려주는 도구입니다. 서버도 데이터베이스 서버도 필요 없습니다 — 폴더 하나면 됩니다.

01

한눈에

세 문장으로 요약하면 이렇습니다.

  1. 회사 목록(워치리스트)을 넣으면, 도구가 각 회사 사이트를 실제 Chromium으로 열어 9가지 층에서 증거를 모읍니다.
  2. 모은 증거를 벤더 지문에 대조해 확정 / 추정 / 미검출을 매기고, 판정 근거를 함께 저장합니다.
  3. 매주 반복하면서 지난주와 달라진 것 — 새로 들어온 솔루션, 빠진 솔루션, A→B 교체, 아무것도 안 쓰는 회사 — 를 신호로 뽑아줍니다.
이 도구가 묻는 질문

"이 사이트가 무엇을 쓰는가"가 아닙니다. "이번 주에 어떤 회사가 영업하기에 더 흥미로워졌는가, 그리고 왜?"입니다. 그래서 한 번 조회가 아니라 매주 관측이고, 판정 하나하나가 근거를 달고 다닙니다.

벤더 중립입니다. 특정 솔루션 회사 소속이 아니어도 그대로 쓸 수 있고, 소속이라면 설정 한 줄로 "우리 것이 빠졌다"를 따로 알려 받을 수 있습니다. LLM은 쓰지 않습니다 — 같은 증거는 언제나 같은 판정입니다.

02

설치

필요한 것
Python 3.11 이상 · 디스크 약 200MB(브라우저 포함) · 인터넷
되는 OS
Linux · macOS · Windows (Windows는 radar.exe로 실행; 코드에 OS 분기가 없습니다)
필요 없는 것
Docker · DB 서버 · 클라우드 계정 · API 키

  1. 저장소를 받고 가상환경에 설치합니다.

    git clone <저장소 주소> martech-radar
cd martech-radar
python3 -m venv .venv
.venv/bin/pip install -e .          # Windows: .venv\Scripts\pip install -e .

  2. 브라우저를 한 번 내려받습니다. (Playwright가 관리하는 Chromium, 약 170MB)

    .venv/bin/playwright install chromium

  3. 설치가 됐는지 확인합니다. 아무 폴더에서나 됩니다.

    .venv/bin/radar home
/home/you  (cwd)
  · radar.toml
  · targets.yaml
  · data/radar.db
  · fingerprints  (using the shipped set)

    점(·)은 "아직 없음"입니다. 다음 절에서 만듭니다.

팁

매번 .venv/bin/radar라고 치기 번거로우면 .venv/bin을 PATH에 넣거나 가상환경을 활성화하세요. 이 문서는 이후 그냥 radar로 씁니다.

03

워크스페이스 — 내 것이 전부 들어 있는 폴더

설치한 코드와 내 데이터는 다른 곳에 삽니다. 코드는 가상환경 안에, 데이터는 워크스페이스라는 폴더 하나에.

<워크스페이스>/ radar.toml 설정 — 언어, 지역, 접근 토큰 targets.yaml 워치리스트 씨앗 (실제 목록은 DB에 삽니다) data/radar.db 모든 스캔·증거·판정·대기열 — 이 배포의 기억 전부 data/logs/ 주간 요약 fingerprints/ (선택) 기본 지문을 덮어쓰고 싶을 때만

이 폴더 밖에는 아무 상태도 없습니다. 그래서 옮기는 것도, 백업하는 것도, 한 컴퓨터에서 두 배포를 돌리는 것도 전부 "폴더" 단위입니다(§08).

도구가 워크스페이스를 찾는 순서

  1. radar --home DIR … 로 직접 지정
  2. 환경변수 RADAR_HOME
  3. 그것도 없으면 지금 있는 폴더

radar home이 언제나 "지금 어느 폴더를 쓰고 있는지"를 보여줍니다. 데이터가 비어 보이면 가장 먼저 이 명령을 치세요 — 십중팔구 다른 폴더를 보고 있는 겁니다.

04

첫 스캔까지 — 10분

  1. 워크스페이스 폴더를 만들고 들어갑니다. 이름과 위치는 자유입니다.

    mkdir ~/radar-home && cd ~/radar-home

  2. 예시 파일 두 개를 복사합니다.

    cp /path/to/martech-radar/targets.example.yaml targets.yaml
cp /path/to/martech-radar/radar.example.toml   radar.toml

  3. radar.toml을 엽니다. 한국에서 쓰신다면 세 줄만 바꿉니다.

    [scan]
locale = "ko-KR"          # 사이트는 지역마다 다른 태그를 내립니다
timezone = "Asia/Seoul"

[ui]
language = "ko"

    나머지는 기본값으로 두셔도 됩니다. 특히 respect_robots = true는 그대로 두세요 — 사이트가 "들어오지 마라"고 한 곳은 건너뜁니다(§10).

  4. targets.yaml을 엽니다. 업종을 먼저 선언하고, 회사를 적습니다.

    industries:
  retail:  { label: 리테일·이커머스 }
  travel:  { label: 여행·숙박 }

targets:
  - id: shop_a              # 이력의 열쇠. 한 번 정하면 바꾸지 마세요
    company: A 쇼핑몰
    industry: retail        # 위에 선언한 코드만 됩니다
    urls:
      - https://shop.example/
      - https://shop.example/product/1   # 상세페이지도 같이 — 거기서만 뜨는 SDK가 있습니다

  5. 목록을 DB에 넣고, 첫 스캔을 돌립니다. URL 하나에 10초 안팎입니다.

    radar watchlist import targets.yaml
imported 3 new, 0 updated, 2 industries

radar batch
run 1: 3 targets, 4 urls, concurrency 3
  [1/4] shop_a         OK           15D/ 2P  https://shop.example/
  [2/4] shop_a         OK           12D/ 1P  https://shop.example/product/1
  ...

    15D/ 2P는 확정 15개, 추정 2개입니다. OK가 아닌 상태(차단됨·시간초과 등)는 §09에서 설명합니다.

  6. 대시보드를 엽니다.

    radar serve
dashboard on http://127.0.0.1:8848  (no token — local only)

    브라우저로 http://127.0.0.1:8848 에 들어갑니다.

이제부터 YAML은 안 써도 됩니다

목록은 DB에 살고, 대시보드의 "관리" 페이지에서 회사를 추가·수정·일시중지하고 스캔을 예약할 수 있습니다. 파일로 다시 꺼내고 싶으면 radar watchlist export -o 파일.yaml.

05

대시보드 — 여섯 페이지

페이지무엇을 보나
개요업종별로 누가 engagement 플랫폼을 쓰고, 누가 안 쓰고, 누구는 판정을 못 했는지. 벤더 점유율.
신호함이번 주에 바뀐 것, 급한 순서로. 아래엔 "임계값 미달"과 "판정 불가" 목록도 — 숨기지 않습니다.
기업워치리스트 전체. 업종·상태로 거릅니다.
기업 상세현재 스택. 판정 하나를 펼치면 그렇게 본 실제 증거(어느 층, 어떤 패턴, 실제로 본 문자열)가 나옵니다. 실행 타임라인도.
솔루션벤더별 점유 — 누가 무엇을 쓰는지 역추적.
지문판정 규칙 열람. 패턴 하나를 저장된 모든 증거에 대조해 보는 시험 도구가 있습니다 — 지문을 추가하기 전에 남의 것에 걸리는지 미리 봅니다.
관리회사 추가·수정·일시중지, 업종 추가, 스캔 예약. 저장한 대로 다음 스캔에 반영됩니다.

모든 판정에서 원본 증거까지 클릭 두 번이면 닿습니다. "그걸 어떻게 아느냐"는 질문에 페이지를 안 떠나고 답할 수 있게 만든 것이 이 대시보드의 목적입니다.

06

매주 돌리기

변화를 보려면 같은 일을 같은 방식으로 반복해야 합니다. 손으로 하면 두 가지입니다:

radar batch          # 전체 스캔 (또는 대시보드 "전체 스캔 예약")
radar digest         # 이번 주 한 장 요약 — 변화·공략 가능·미달·판정불가

자동으로 돌리고 싶으면 bin/weekly-scan이 스캔 → 요약 파일 저장 → 오래된 로그 정리를 한 번에 합니다. 동시에 두 개가 돌지 않도록 잠금도 잡습니다.

# Linux/macOS, 매주 월요일 07:00
crontab -e
0 7 * * 1 RADAR_HOME=/home/you/radar-home /path/to/martech-radar/bin/weekly-scan

Windows는 작업 스케줄러에 같은 명령을 등록합니다. 요약은 <워크스페이스>/data/logs/digest-날짜.md에 쌓입니다.

이탈 판정은 2주가 걸립니다

한 번 안 보인 벤더는 이탈 후보일 뿐이고, 연속 두 번 안 보여야 이탈 확정입니다. 첫 주엔 "후보"만 나옵니다 — 정상입니다. 서두르라고 만든 도구가 아닙니다.

07

대시보드와 워커 실행

대시보드는 스캔을 예약하고 워커가 실행합니다. 같은 컴퓨터의 로컬 워크스페이스를 사용하세요. SQLite DB를 네트워크 드라이브나 동기화 폴더로 공유하는 구성은 권장하지 않습니다.

radar --home /path/to/workspace serve
radar --home /path/to/workspace worker --watch

서버에서 실행한다면 기본 localhost 바인딩을 유지하고 SSH 터널로 접속하세요. 접근 토큰만으로 브라우저의 네트워크 접근을 격리할 수는 없습니다.

08

옮기기 · 백업 · 여러 개 돌리기 — 전부 "폴더"

하고 싶은 것하는 법
다른 컴퓨터로 이전워크스페이스 폴더를 복사 → 거기서 설치(§02) → radar --home 그폴더 home. 끝. 이력·판정·대기열 전부 따라갑니다.
백업폴더를 복사. 실행 중에는 radar backup을 사용하세요. 폴더를 직접 복사하려면 대시보드와 워커를 먼저 종료하세요.
배포 두 개 (예: 한국 / 일본)폴더 두 개. radar --home ~/kr-home …, radar --home ~/jp-home …. 설정·목록·데이터가 서로 안 섞입니다.
코드 업데이트cd martech-radar && git pull && .venv/bin/pip install -e .. 워크스페이스는 건드리지 않습니다. DB 스키마가 바뀌면 다음 실행 때 자동으로 제자리에서 올라갑니다(삭제 없음).
지문(판정 규칙) 업데이트 후radar redetect --diff — 저장된 과거 스캔 전부를 새 규칙으로 다시 판정하고, 무엇이 바뀌었는지를 줄마다 보여줍니다. 사이트는 재방문하지 않습니다.

이게 가능한 이유는 한 가지입니다 — 워크스페이스 밖에 상태가 없고, 코드는 워크스페이스가 어디에 있는지 신경 쓰지 않기 때문입니다. 설정과 DB를 함께 옮기면 저장된 이력을 이어서 사용할 수 있습니다.

09

결과 읽는 법 — 헷갈리기 쉬운 것들

스캔 상태

상태뜻판정에 쓰나
OK정상 관측예 — 유일하게
BLOCKED봇 차단벽이 대신 응답아니오
SKIPPED_BY_ROBOTS사이트의 robots.txt가 금지 — 방문하지 않음아니오
THIN200으로 응답했지만 점검 안내 페이지아니오
PARTIAL평소보다 훨씬 적게 로드됨 — 반쯤 열린 페이지아니오
TIMEOUT · NAV_FAILED응답 없음 · 접속 실패아니오

판정에 안 쓰이는 상태는 이력에서 그 주가 없던 것처럼 취급됩니다. 그래서 차단된 주가 "벤더가 빠졌다"로 둔갑하지 않습니다. 이게 이 도구에서 가장 중요한 규칙입니다.

판정

판정뜻
DETECTED 확정브라우저가 그 벤더에 접속했거나 그 코드가 실행됐다 — 직접 증거
PROBABLE 추정약한 직접 증거 하나뿐이거나, CSP 헤더·번들 안에 이름만 있다
NOT_DETECTED 미검출"안 쓴다"가 아니라 "우리가 못 봤다". 동의 배너 뒤, 로그인 뒤, 안 본 페이지에 있을 수 있습니다
고객 앞에서

"귀사는 CRM이 없으신 것으로 확인됩니다"라고 말하면 안 됩니다. 우리가 아는 건 우리가 본 페이지에서 보이지 않았다는 것뿐입니다. "확인되지 않았습니다"까지만.

신호

급한 순서입니다. [vendor] home을 설정하지 않으면 "자사" 신호는 나오지 않고 모든 벤더가 동등합니다.

HOME_MIGRATION우리 제품이 빠지고 누가 들어왔는지까지 보인다 — 가장 급함
HOME_REMOVAL우리 제품이 빠졌고 후임은 아직 안 보임
COMPETITOR_MIGRATION경쟁사끼리 교체 — 진입 창
COMPETITOR_REMOVAL경쟁사 이탈, 후임 미확인
GREENFIELD광고·애널리틱스는 성숙한데 engagement 플랫폼이 없음 — 가장 좋은 입구
COMPETITOR_NEW / HOME_NEW신규 진입
10

자주 묻는 것

데이터가 비어 있어요

radar home부터. 다른 폴더를 보고 있을 확률이 가장 높습니다. 맞는 폴더면 radar watchlist list로 목록이 있는지 확인하세요.

어떤 회사가 계속 SKIPPED_BY_ROBOTS예요

그 사이트의 robots.txt가 일반 방문 봇을 금지한 겁니다. 꽤 흔합니다. 그래도 봐야 할 근거가 있으면 관리 페이지에서 그 회사만 예외로 두되 사유를 적어야 저장됩니다 — 나중에 누구든 왜 그랬는지 볼 수 있게요. 전역 스위치가 아니라 회사 단위 결정입니다.

어떤 회사는 벤더가 너무 적게 잡혀요

금융·보험처럼 동의 배너 뒤에 태그를 묶는 사이트는 실제보다 얇게 보입니다. 이 도구는 배너를 클릭하지 않습니다(원칙). 상세페이지 URL을 추가하면 나아지는 경우가 많습니다.

새 벤더를 추가하고 싶어요

① 대시보드 "지문"에서 후보 패턴을 저장된 증거 전체에 대조해 봅니다(남의 것에 걸리는지). ② fingerprints/*.yaml에 추가합니다 — 워크스페이스에 fingerprints/ 폴더를 두면 기본 세트 대신 그걸 씁니다(복사 후 추가). ③ radar redetect --diff. 짧은 전역변수(ab, hj)나 파일명(at.js)은 weak_signals로 두거나 경로에 앵커를 거세요 — 오탐을 줄이기 위한 규칙입니다.

스캔이 느려요

URL당 10초 안팎이 정상입니다(사이트가 다 뜨기를 기다립니다). radar.toml의 concurrency를 올리면 빨라지지만, 같은 사이트엔 1초 간격을 지킵니다. 실행 시간은 사이트와 장비에 따라 달라집니다.

Windows에서 bin/radar가 안 돼요

그건 소스 체크아웃용 bash 스크립트입니다. Windows에서는 .venv\Scripts\radar.exe(설치된 콘솔 스크립트)를 쓰세요. 정직하게 말씀드리면, Windows 래퍼는 저희가 직접 실행해 보지 못했습니다 — 문제가 있으면 알려주세요.
